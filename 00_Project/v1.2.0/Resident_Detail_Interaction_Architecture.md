# Resident Detail Interaction Architecture

## Entry
- Profile Center -> 今日办公室 -> 居民 -> Resident Detail Panel.

## ViewModel
- `ResidentDetailViewModel` is a UI-only projection.
- It is generated by `SecondWorldEngine.getResidentDetailViewModel(residentId)`.
- It does not save business state.

## Runtime Boundary
- UI reads Provider.
- Provider calls `SecondWorldEngine`.
- `SecondWorldEngine` reads existing resident, relationship, memory, story, rumor, event, career, skill, influence, and save runtime state.
- UI submits `PlayerActionRequest`.
- `SecondWorldEngine.submitPlayerAction` returns `PlayerActionResult`.

## No New Top-Level Runtime
- No `ResidentDetailManager`.
- No `ResidentInteractionEngine`.
- No `ResidentProfileRepository`.
- No new JSON type.

## Interaction Flow
1. Office Hub reads `InteractiveOfficeSnapshot`.
2. Resident list selects a resident id.
3. Detail panel renders `ResidentDetailViewModel`.
4. Interaction button creates `PlayerActionRequest`.
5. Provider calls `SecondWorldEngine.submitPlayerAction`.
6. Engine applies existing runtime logic.
7. Provider invalidates only office and selected resident projections.
8. UI shows `PlayerActionResult`.

## Visibility
- Stranger sees basic fields only.
- Acquaintance sees general interests and topics.
- Familiar sees shared memory hints.
- Friend sees preference and trust summary.
- Close or trusted friend sees deeper relationship history hints.

## Transaction Safety
- Duplicate action ids are blocked by existing processed office event ids.
- Share fish is blocked unless action metadata includes a fish id.
- Unsupported actions return safe blocked results.

## Save Compatibility
- Uses existing save fields:
  - `recentPlayerActions`
  - `processedOfficeEventIds`
  - `friendshipStates`
  - `socialInteractionHistory`
  - `interactionHistory`
- No new save version requirement.
